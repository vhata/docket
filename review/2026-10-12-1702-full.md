## Summary

This is the first codebase review. The gates are green, but several of them check less than they appear to. The installer is where the serious defects are. Its handling of the Docket section assumes every settings value fits on one `- Name: value` line in an LF file with unique markers. A wrapped bullet loses its continuation lines on every resync, and CRLF, symlinked or fenced-marker files produce duplicated or misplaced sections. The PR body parser shared by `check-pr-markers.sh` and `pr-labels.sh` is the second cluster. Its comment and fence stripping misreads ordinary Markdown: an inline `<!--` hides the rest of the body, and a Validation section that is all code counts as empty. Its near-miss rule also rejects hard-wrapped prose. The fixture suites pass, but mutation testing removed many of the rules they appear to cover without a failure. One fixture depends on today's date and will fail every CI run from 2026-10-27. The documentation largely agrees with the scripts; the six small disagreements are fixed on this branch. Three open rule-text disagreements need the user's decision.

## Invariants

Carried from `ARCHITECTURE.md#invariants`, unchanged: bash 3.2 plus git and `gh`; `docket/` byte-identical to `templates/docket/`; parsed documents are interfaces changed together with a fixture; templates name no project; every rule has one home; the installer writes only its listed paths and never deletes.

Added by this review. Each is relied on by the code today, and at least one finding shows it being broken or held only by accident:

- Fixtures run the scripts under the shell they claim to test. Calling `bash` from a suite started under `/bin/bash` resolves through PATH (`fixtures-run-scripts-under-path-bash`).
- No fixture's outcome depends on the wall-clock date (`review-due-fixture-date-time-bomb`).
- A check that guards a destructive action fails closed. When the check itself errors, the action is skipped and reported (`cleanup-landed-status-error-treated-clean`, `cleanup-landed-locked-worktree-aborts-run`).
- The installer reads and writes `AGENTS.md` and `CLAUDE.md` only as regular files inside the repository, and recognises markers and the import line regardless of line endings and outside fenced code. A settings bullet is the bullet line plus its indented continuation (`wrapped-setting-bullets-truncated`, `crlf-agents-md-duplicate-section`, `agents-md-symlink-written-through`, `fenced-marker-example-replaced`).
- `check-pr-markers.sh` and `pr-labels.sh` carry one body-cleaning program, one change-type list and one marker grammar in two copies. The copies must stay identical, and the cleaning must not hide text that GitHub renders (`unterminated-comment-opener-swallows-body`).
- Slugs match `[a-z0-9][a-z0-9-]*` everywhere, because the scripts interpolate them unescaped into grep and awk regexes. Every validator that accepts a slug enforces the form (`check-queues-finding-slugs-unvalidated`).
- `claim-check.sh`'s worktree directory pattern `(todo|review|roadmap|fix|task)-<slug>` matches `start-work.sh`'s `<dir>/<queue>-<slug>` naming and queue list.
- In `review/README.md` the index table precedes any other table with a backticked commit, because `review-due.sh` takes the first such row as the latest review.
- Gate diagnostics reach the person whose commit or push was refused. A hook that silences a gate's stdout must not lose the reason (`pre-commit-hides-failure-reasons`).
