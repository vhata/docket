# Agent guide: the docket skill repository

This file is for work on the docket skill itself. An agent using the skill in another project starts at `SKILL.md` and ignores this file, which travels with every clone or subtree of the skill.

This repository is the docket skill: `SKILL.md` and `references/` are what an agent reads when it uses the skill, `templates/` is what the skill installs into a project, `install.sh` does the installing, and `tests/` checks the scripts and the installer. The repository also runs on docket itself, with its own vendored `docket/`, queues and review ledger. [ARCHITECTURE.md](ARCHITECTURE.md) describes the parts and the invariants between them; [docs/QUALITY.md](docs/QUALITY.md) the gates.

## Docket

This project is run with docket. Read [docket/CONTRACT.md](docket/CONTRACT.md) before any work; it is the authoritative workflow, and this section records only this project's settings. The installer keeps this section current: the text above the list is rewritten on every run, the list keeps the values this project has set, and the section may sit anywhere in this file.

- Queue areas: `[INSTALLER]` (`install.sh`), `[SCRIPTS]` (`templates/docket/scripts/`), `[GUIDES]` (`SKILL.md`, `references/`, the guides in `templates/docket/`), `[TEMPLATES]` (the rest of `templates/`), `[TOOLING]` (`tests/`, `scripts/`, hooks, CI), `[DOCS]` (README and this repository's own documents).
- Concurrency cap: none; the test suites build only small scratch repositories.
- Merging and releases: the user merges unless delegated in the turn. There are no release tags; projects install from `main`.
- Optional pieces in force: review ledger, stacked PRs, scheduled validation of main; the roadmap queue is not in use.
- Environment: run tests under macOS `/bin/bash` (3.2) as well as a current bash; the git identity for this repository is `jonathan.hitchcock@gmail.com`; sub-agents keep scratch files in their own worktree's `.docket/` or a `mktemp` path, never a shared fixed name.
- Self-hosting: `docket/` here is generated from `templates/docket/`. Edit `templates/docket/`, then run `bash install.sh --self` and commit both; CI fails a PR whose `docket/` does not match.

## Working on the skill

- The shipped machinery is `templates/docket/`. Never edit `docket/` by hand; it is this repository's installed copy and is regenerated by `bash install.sh --self`.
- Everything under `templates/` is written for a project that is not this one. Keep this repository's names, paths and history out of it.
- A change to a script's behaviour comes with a fixture in `tests/scripts.sh` or `tests/install.sh`, and with the documentation that describes the behaviour (`SKILL.md`, `references/`, the vendored guides, `README.md`) updated in the same PR.
- PR descriptions become squash-merge commit messages (the contract has the wrapping rule). They describe the final change: no stacking or merge-order notes, no to-dos, no instructions to reviewers, no review-cycle history, and no changelog of revisions. The independent review and its dispositions go in a PR comment headed `## Review`; anything else transient goes in a PR comment too.
